# 실습 꾸러미 05 — 홈페이지 의뢰

## 상황

박팀장이 "스마트폰·AI 생활교실" 소개 페이지를 한 장 만들어 달라고 의뢰서를 보냈습니다. 홈페이지 업체 반짝웹에 맡기면 2주가 걸린다고 해서, 우선 우리가 직접 시안을 만들어 보기로 했습니다. 재료는 `의뢰자료/` 폴더에 있는 의뢰서, 김전임이 정리하다 만 프로그램표, 복지관 소개 원문, 로고와 삽화입니다. 시안을 돌리자마자 `수정요청/` 폴더로 메일이 몇 통 들어올 예정입니다.

코드를 몰라도 괜찮습니다. 클로드 코드에게 말로 시키고, 결과는 브라우저로 눈으로 확인합니다.

## 목표

- 꾸러미 폴더 안에 `index.html` 한 장짜리 소개 페이지가 있습니다.
- 수정 요청 메일이 순서대로 반영되어 있고, 무엇을 어떻게 고쳤는지 알 수 있습니다.

## 과제

### 기본 (실습 3-1 첫 웹페이지)

1. 클로드에게 `의뢰자료/` 안의 파일을 모두 읽게 하고, 페이지에 들어갈 내용을 먼저 정리해 보여 달라고 하세요. 바로 만들게 하지 말고 계획부터 받습니다.
2. 계획을 확인한 뒤 `index.html`을 만들게 하세요. 이미지는 `의뢰자료/이미지/`의 그림을 씁니다.
3. 만든 페이지를 브라우저로 여세요. ("브라우저로 열어 줘"라고 말하면 됩니다.)
4. 페이지에 올라간 날짜·강사·전화번호가 원자료와 맞는지 직접 확인하세요.

### 기본 (실습 3-2 반복 개선)

5. `수정요청/` 폴더의 메일을 **번호 순서대로 한 통씩** 클로드에게 반영시키세요. 한 번에 여러 통을 몰아서 시키지 않습니다.
6. 한 통을 반영할 때마다 브라우저를 새로고침해 결과를 눈으로 확인한 뒤 다음 메일로 넘어갑니다.

### 도전

7. 메일끼리 서로 부딪치는 요청이 있습니다. 둘 다 만족시킬 조율안을 클로드와 함께 만들고, 어떤 요청을 어떻게 절충했는지 이유를 `수정기록.md`에 남기세요.
8. 휴대폰 화면 폭에서 페이지가 어떻게 보이는지 확인하세요. (브라우저 개발자 도구의 휴대폰 보기, 또는 창을 좁게 줄여 봅니다.)
9. 어르신이 읽기에 글씨 크기·대비·버튼 크기가 충분한지 클로드에게 점검 기준을 세워 달라고 하고, 그 기준으로 페이지를 점검하세요.

## 완료 기준

- [ ] `index.html`을 브라우저로 열면 교실 소개, 일정, 신청 방법이 한눈에 보인다.
- [ ] 페이지에 올라간 신청 전화번호가 하나뿐이고, 어느 번호가 맞는지 사람이 확인했다.
- [ ] 프로그램표에서 빈칸이거나 이상한 값이 그대로 올라가지 않았다(확인 필요로 표시했거나 사람이 채웠다).
- [ ] 수정 요청 메일 4통이 순서대로 반영되었다.
- [ ] 창을 휴대폰 폭으로 줄여도 글자가 잘리거나 옆으로 밀려나지 않는다.
- [ ] (도전) `수정기록.md`에 충돌한 요청과 절충 이유가 적혀 있다.
